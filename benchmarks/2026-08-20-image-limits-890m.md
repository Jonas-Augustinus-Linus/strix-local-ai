# 890M 이미지 생성 한계 실측 — ComfyUI 단독 (2026-08-20)

**목적**: 다른 작업 다 끄고 ComfyUI 단독으로 GTT(26GiB) 한계까지 밀어 최고 품질 지점 확인.

## baseline (단독, idle)
- 시스템 RAM 29GiB 중 3.8G 사용 / 25G 가용, GTT 0.4G

## 부하별 실측 (Illustrious XL, 24~28 steps, euler_a)

| 설정 | GTT 피크 | 시간 | 결과 해상도 |
|---|---|---|---|
| 1장 1024 기본 | 15.4G | 56초 | 1024² |
| 1장 hires 1.5x | 20.7G | 2.5분 | 1248×1824 |
| 1장 hires 2.0x | 20.6G | 4.4분 | 1664×2432 |
| 배치4 1024 | 9.0G | 3분 | 1024² ×4 |
| 배치4 + hires 1.5x | 11.5G | 5분 | 고해상 ×4 |
| 배치2 + hires 1.5x | 20.6G | ~2.5분 | 고해상 ×2 |

## 핵심 결론

1. **GTT는 병목이 아니다** — 가장 무거운 hires도 20.7G (상한 26에 5G+ 여유). 절대 안 죽는다.
2. **배치는 GTT를 거의 안 쓴다** — 배치4가 9G. latent가 작아 메모리 부담 미미, 시간만 선형 증가.
3. **진짜 병목은 890M 연산 속도** — GTT를 더 줘도 안 빨라진다. 품질/장수를 올리면 시간이 는다.
4. **스윗스팟**:
   - 품질: **hires 1.5x** (2.0x는 시간 2배인데 이득 적음)
   - 여러 장: 배치 2~4 (GTT 안전, 시간 감수)
   - 최고 조합: **배치2 + hires 1.5x** (고해상 2장, GTT 20.6G, ~2.5분)

## 페이지 반영 (simple-image.html)
- 장수 드롭다운 1/2/4, hires 토글(기본 ON), 갤러리로 여러 장 표시
- 예상 시간 자동 표시 (장수×hires 반영), 대기 타임아웃 동적 확장
