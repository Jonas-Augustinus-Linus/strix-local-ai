# LoRA 데이터 준비 레포트 (앞으로 계속 쓰는 참조서)

LoRA 품질의 **90%는 데이터**에서 결정된다. 모델 설정은 나머지 10%. 이 문서는 매번 데이터를
준비할 때 따라 하는 실전 레퍼런스다. (훈련 실행은 [lora-training-ko.md](lora-training-ko.md), 도구는 `scripts/prep_lora_data.py`)

## 0. 먼저: 무슨 LoRA인가 — 종류가 전략을 정한다

| 종류 | 예 | 장수 | 다양성 | 캡션 전략 |
|---|---|---|---|---|
| **인물/얼굴** | 특정 사람 | 20~40 | 각도·표정·조명 다양, 배경 다양 | 트리거 + **변하는 것만**(옷/배경) |
| **캐릭터** | 내 창작 캐릭터 | 15~40 | 여러 포즈·의상·표정 | 트리거 + WD14 태그 |
| **화풍/스타일** | 특정 작가풍 | 20~50 | **소재는 다양**(인물·사물·풍경 섞기) | **트리거만**(세부 캡션 최소) |
| **개념/의상** | 특정 한복·소품 | 15~30 | 그 개념이 명확히 보이게 | 트리거 + 개념 태그 |

핵심 규칙: **일관되게 할 것 = 대상**, **다양하게 할 것 = 나머지(배경·포즈·조명)**.
인물 LoRA인데 같은 사진만 20장이면 그 각도만 배운다.

## 1. 좋은 이미지의 조건

- **해상도 ≥ 1024**(짧은 변). 작으면 디테일을 못 배움. `prep_lora_data.py`가 축소만 하고 확대는 안 함(작은 건 경고).
- **대상이 크고 선명**, 초점 맞음. 흐리거나 대상이 작으면 제외.
- **배경 방해 최소**(인물/개념), 또는 **다양한 배경**(과학습 방지). 스타일은 소재 자체가 다양해야.
- **다양성**: 같은 구도 반복 금지. 각도·조명·표정·거리(클로즈업/전신)를 섞어라.
- **일관성**: 배우게 할 대상은 프레임마다 동일. (인물이면 같은 사람, 스타일이면 같은 화풍)
- **금지**: 워터마크·텍스트·콜라주·심한 필터·잘린 얼굴·다른 사람 섞임.

## 2. 몇 장? — 질 > 양

- 기본 **15~40장**. 스타일은 20~50장.
- **좋은 20장 > 나쁜 100장.** 애매한 이미지를 넣으면 그 애매함을 배운다.
- 처음엔 **20~30장 + 1500스텝**으로 가볍게(890M에선 몇 시간). 결과 보고 늘린다.

## 3. 캡션 전략 (가장 자주 틀리는 부분)

**원칙: "가르치려는 것은 캡션에서 빼고, 변하는 것만 적는다."**
캡션에 적은 것은 "이건 트리거와 별개의 변수"라고 모델에 알리는 것 → 안 적으면 트리거가 그걸 흡수한다.

- **트리거 단어**: 흔치 않은 고유어를 정한다(예: `ohwxwoman`, `myhanbok`, `jkstyle`). 나중에 프롬프트에 이 단어를 넣어 불러낸다. 흔한 단어(woman, hanbok)를 트리거로 쓰면 기존 개념과 충돌.
- **인물 LoRA**: `트리거, wearing red dress, outdoor, smiling` — **얼굴 특징은 캡션 안 함**(트리거가 얼굴을 흡수). 옷·배경·표정만 적어 변수로 분리.
- **스타일 LoRA**: **트리거만**(또는 아주 최소). 스타일 요소를 캡션하면 그게 변수가 되어 스타일을 안 배운다.
- **캐릭터/개념**: 트리거 + 그 프레임에서 변하는 것(포즈·배경·의상). WD14 자동 태깅 후 **트리거를 맨 앞에 추가**.
- **캡션 없으면**: 폴더 이름이 트리거가 됨(가장 단순, 스타일 LoRA엔 이걸로 충분).

## 4. 이미지 어디서 — 합법·윤리 + 자가생성

- **가장 안전**: 본인이 찍은 사진 / 본인이 소유한 이미지 / 라이선스 명확한 것.
- **자가생성(강력 추천)**: **이 박스로 뽑은 이미지를 LoRA 데이터로.** 예) Z-Image/HiDream으로
  다양한 한복 인물 30장 생성 → SDXL 한복 스타일 LoRA. 외부 데이터 0으로 순환 학습 가능
  (내가 뽑은 베스트 컷을 자산으로 쌓는 피드백 루프). → 아래 §7.
- **정책**: 무검열-only는 유지하되, 실존 인물의 얼굴을 무단 학습·배포하는 건 책임 문제.
  로컬 실험은 자유, **배포 시 책임은 배포자**(프로젝트 매니페스토).

## 5. 이 박스 파이프라인 (턴키)

```bash
# 1) 원본 폴더 → 정규화(1024, PNG, 알파제거) + 검증 + 트리거 캡션
/home/amd-ai/venvs/lora/bin/python scripts/prep_lora_data.py <이름> \
    --src ~/원본폴더 --trigger <트리거단어>
#    → ~/lora-data/<이름>/img/ 에 001.png + 001.txt … 생성, 장수/해상도/중복 리포트

# 2) (캐릭터/개념) 자동 태깅이 필요하면
/home/amd-ai/venvs/lora/bin/pip install onnxruntime   # 최초 1회
python scripts/prep_lora_data.py <이름> --src ~/원본 --trigger <트리거> --wd14

# 3) 훈련 (채팅·이미지 끄고 GPU 독점, 밤에)
systemctl --user stop comfyui.service llama-router.service
scripts/lora-train.sh <이름>          # 기본 1500스텝
systemctl --user start llama-router.service   # 끝나면 복원

# 4) 사용: 프롬프트에 <트리거단어> 넣기 (ComfyUI LoraLoader 또는 트리거)
```

**아키 주의**: `lora-train.sh`는 **SDXL LoRA**(Illustrious 베이스) → SDXL 모델에만 붙음.
Z-Image/FLUX LoRA는 별도 도구(AI Toolkit). ([lora-training-ko.md](lora-training-ko.md) §0 참조)

## 6. 최종 체크리스트 (훈련 전)

- [ ] 대상이 모든 이미지에서 일관되고 선명한가?
- [ ] 배경·포즈·조명이 충분히 다양한가?(과학습 방지)
- [ ] 해상도 ≥1024, 워터마크·텍스트·타인 섞임 없나?
- [ ] 트리거는 흔치 않은 고유어인가?
- [ ] 캡션: 가르칠 것은 빼고 변하는 것만 적었나?(스타일은 트리거만)
- [ ] 15~40장(스타일 20~50) 범위인가?

## 7. 자가 데이터셋 생성 레시피 (외부 이미지 0)

이 박스의 강점 — 좋은 이미지를 이미 뽑을 수 있으니, 그걸로 데이터를 만든다:

1. **일관 주제로 대량 생성**: Z-Image/HiDream으로 같은 컨셉(예: 한복)을 배경·포즈·조명만 바꿔 30~50장.
2. **선별**: 손·얼굴 깨진 것 버리고 베스트 25~35장.
3. `prep_lora_data.py <이름> --src ~/사진/strix-ai/<배치> --trigger <트리거>`.
4. `lora-train.sh <이름>` → 그 컨셉을 **SDXL에서도** 빠르게 뽑는 LoRA 완성.

→ Z-Image(느리지만 최고품질)로 데이터를 만들어 SDXL(빠름)에 스타일을 이식하는 게 특히 실용적이다.

## 요약
- 종류(인물/캐릭터/스타일/개념)가 데이터·캡션 전략을 정한다.
- 대상=일관, 나머지=다양. 질>양(20~40장).
- 캡션은 "변하는 것만". 스타일은 트리거만.
- 도구: `prep_lora_data.py`(정규화·검증·캡션) → `lora-train.sh`(훈련).
- 외부 데이터 없으면 **우리 모델로 데이터를 생성**해 순환 학습.
